# Implementation Plan: Autonomous Career Co-Pilot

This plan breaks down the transformation of TalentRadar into a high-tier portfolio project. The work is divided into logical, deliverable phases. You can complete this one phase at a time, and each phase will yield a working, demonstrable feature.

## Phase 1: Foundation & Cleansing (The Cleanup)
*Goal: Remove the technical debt and set up a robust, scalable architecture.*

- **Action 1.1: Purge the Fake Code:**
  - Delete `agents/ml_scorer.py`.
  - Delete mocked endpoints (`_handle_company_info`, etc.) in `agents/orchestrator.py`.
  - Remove fragile regex JSON parsing and replace it with `pydantic` schemas for structured LLM outputs.
- **Action 1.2: Upgrade the Vector Store:**
  - Introduce **Hybrid Search**. Keep ChromaDB (or swap to Qdrant) but configure it so we can filter by metadata (like location and remote status) directly in the database query, completely removing the `O(N*M)` Python filtering loop in `rag_agent.py`.
- **Action 1.3: Fix the N+1 Database Issue:**
  - Rewrite `search_jobs_semantic` to fetch all retrieved `job_ids` in a single SQLAlchemy batch query (`SELECT * FROM jobs WHERE id IN (...)`).
- **Action 1.4: Setup Asynchronous Workers:**
  - Introduce **Celery** (using the existing Redis container as the message broker). This will be used for long-running tasks like generating custom resumes and evaluating candidates without blocking the API.

## Phase 2: Data Engineering Pipeline (The Engine)
*Goal: Prove you can ingest, clean, and manage data autonomously.*

- **Action 2.1: Scraper Development:**
  - Write a robust Python scraper (using `Playwright` or `BeautifulSoup`) to pull jobs from a real source (e.g., HackerNews 'Who is Hiring', or a public job board API).
- **Action 2.2: LLM Data Normalization:**
  - Create a pipeline step where an LLM cleans the scraped data (e.g., classifying unformatted text into standard tags: `Seniority: Mid-level`, `Remote: True`, `Core Skills: [Python, React]`).
- **Action 2.3: Airflow Orchestration:**
  - Write an Airflow DAG (`ingest_jobs_dag.py`) that runs daily: Scrape -> Normalize -> Embed -> Upsert to Postgres & ChromaDB.

## Phase 3: The True AI Core (The Brain)
*Goal: Implement the standout AI features using advanced Agentic patterns.*

- **Action 3.1: LLM-as-a-Judge Matching:**
  - Build the Candidate Evaluator. Create a prompt that takes the Candidate's Resume + Job Description and outputs a strictly typed JSON response: `{ "match_score": 85, "missing_skills": ["Docker"], "reasoning": "..." }`.
  - Wire this up to the Celery queue so users can request a deep evaluation of a job asynchronously.
- **Action 3.2: Skills Gap & Learning Path Generation:**
  - Create an endpoint that analyzes the user's missing skills across their saved/interested jobs and queries the LLM to generate a markdown-formatted structured learning plan.
- **Action 3.3: Dynamic Resume Tailoring:**
  - Build a generation agent that takes the user's base resume and rewrites specific bullet points to align with a target job description, saving the output as a PDF/Markdown.

## Phase 4: Frontend Polish & Market Intelligence (The UI)
*Goal: Create a stunning, interactive interface that wows recruiters.*

- **Action 4.1: Market Intelligence Dashboard:**
  - Build a new Next.js page `/market-trends`.
  - Use `Recharts` to display real-time data from the Postgres database (e.g., "Most in-demand skills this week", "Remote vs. On-site ratio").
- **Action 4.2: Candidate Co-Pilot Interface:**
  - Build the UI for the LLM-as-a-judge results. Use progress bars (0-100 score), colored tags for missing skills (red) and matched skills (green), and a clean expandable card for the LLM's reasoning.
- **Action 4.3: Mock Interview Chat UI:**
  - Build a streaming chat interface where the user can practice answering technical questions generated by the AI based on a specific job posting.
